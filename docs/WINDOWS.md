# Windows + AMD 显卡（ROCm）操作手册

在 Windows 10 19045 + Radeon 7900 XTX 上验证过。下文的 `D:\junqi\` 换成你自己的安装目录。

日常操作都在桌面应用 **军棋 AI 工作台** 里完成：双击桌面上的“军棋 AI 工作台”快捷方式（程序在 `D:\junqi\JunqiStudio\JunqiStudio.exe`）。

```
D:\junqi\
  JunqiStudio\               桌面应用（WPF，.NET 8）
  junqi-ai\                  项目代码（本仓库）
    data\                    自对弈数据
    runs\<名称>\             每次训练一个目录：model.pt、log.jsonl、train.out、summary.json
                             （强化学习另有 ckpt.pt 检查点和 snapshots\ 历史快照）
    logs\play.out            对弈服务的输出
  venv\                      Python 3.12 + PyTorch 2.9.1 + ROCm 7.2.1（AMD Windows 版）
  rocmbench\                 显卡测速脚本（可选，设置页里可改目录）
  shell.bat                  自己建的快捷脚本：进入项目目录并激活 venv（手动敲命令用）
```

`shell.bat` 不在仓库里，内容一行即可：`cmd /k "cd /d D:\junqi\junqi-ai && D:\junqi\venv\Scripts\activate.bat"`。

## 工作台各页面

### 总览

四张卡片，每 2 秒自动刷新：

| 卡片 | 显示 | 按钮 |
|---|---|---|
| 模型训练 | 正在跑（或最近一次）的训练：进度、速度、预计剩余时间、损失与各项命中率 | 查看曲线、停止、新建训练 |
| 人机对弈 | 对弈服务是否在运行、用的是哪个模型 | 打开（进入对弈页）、启动 / 停止 |
| 显卡 | 显卡名称、PyTorch 是否能用、实时占用率与显存 | 测速（约 1 分钟） |
| 引擎自检 | 上次自检结果 | 运行自检（编译引擎 + 全部测试） |

左下角一直显示显卡占用和显存。

### 训练

- 左边是所有训练记录（`runs` 下的目录），带状态：运行中 / 评估中 / 已完成 / 已中断。
- 右边是选中那次训练的详情：
  - 参数一览，五个指标卡（进度、速度、剩余/用时、留出损失、对老师得分）；
  - 四条曲线：损失、走法命中率、猜子命中率、胜负预测准确率。紫线是训练数据上的值，橙点是**没参与训练的留出数据**上的值，两者差不多说明没有过拟合；
  - 训练结束后的对战结果（对随机 AI、规则 AI 各若干局）与猜子对比表；
  - 训练输出（和以前命令行窗口里的内容一样）。
- 按钮：停止训练、用这个模型对弈、照此新建（复制这次的参数）、打开目录。

**新建训练**：先选训练类型。窗口底部实时显示预计用时和实际执行的命令。

- **预训练（行为克隆）**：填名称、选规则、选模型大小（小 0.87M / 中 2.82M / 大 6.57M / 自定义）、勾选训练数据、填步数和学习率等。旧规则产的数据标着“旧规则”，默认不勾选，不要和新规则数据混着训。
- **强化学习（自对弈）**：选一个起点模型（默认选对老师得分最高、且棋盘规则一致的模型），填轮数等。详见下面“强化学习”一节。

- 每次训练用一个新名称，不会覆盖以前的模型。
- 训练在后台进行，**关掉工作台不会停止训练**，再打开工作台会自动接上显示。
- 已停止的训练不能接着跑，只能新建；已保存的模型（每隔“评估间隔”步存一次）会保留。
- 电脑不要睡眠。

参数参考：

| 参数 | 默认 | 说明 |
|---|---|---|
| 训练步数 | 12000 | 时间与它成正比 |
| batch | 1024 | 每步样本数，24GB 显存足够 |
| 学习率 | 6e-4 | batch 越大可以越高；batch 256 时用 3e-4 |
| 精度 | bf16 | 7900 XTX 上比 fp32 快约 1.7 倍 |
| 评估间隔 | 2000 | 每隔多少步在留出数据上评估并保存模型 |
| 对战局数 | 200 | 结束后每种对手下几局，调小能更快出结果 |

7900 XTX 上的速度（bf16，batch 1024）：小模型约 7800、中约 3900、大约 1350 样本/秒。12000 步 × 1024 的中模型约 53 分钟。

#### 强化学习

预训练模型只能学到老师（规则 AI）的水平。强化学习让模型和自己、历史存档、规则 AI 对下，按输赢改进，目标是超过规则 AI。

| 参数 | 默认 | 说明 |
|---|---|---|
| 轮数 | 600 | 每轮：同时下 512 局采样，凑够“每轮样本数”后更新一次模型 |
| 每轮样本数 | 32768 | 中模型每轮约 32 秒 |
| 学习率 | 2e-5 | 比预训练小得多，太大容易把学到的东西冲掉 |
| 评估间隔 | 15 | 每隔几轮用贪心走法对规则 AI 和起点模型各下若干局，并存档 |
| 评估局数 | 400 | 每次评估约 1 分钟；局数越多，得分越准（400 局约 ±0.04） |

训练页上强化学习的四条曲线：

- 对战得分：定期评估的结果，**最重要**。紫线（对规则 AI）稳定高于 0.5 虚线，才说明超过了老师。
- 采样对局中对规则 AI 的得分：每轮都有，但局数少、走法带随机，波动大，看平均线的趋势。
- 策略熵：越低说明走法越果断；降得太快太低可能是过拟合到某种套路。
- 偏离起点模型（KL）：慢慢上升是正常的；涨得很快说明学习率可能太大。

强化学习可以中途停：点“停止训练”，之后点“继续训练”从最近一次存档接着跑（存档之后的几轮会重跑）。

### 对弈

- 选一个模型，点“启动”，棋盘直接显示在工作台里（也可以点右上角在浏览器打开 http://127.0.0.1:8765 ）。
- 换模型：选好后点“换模型重启”。
- 训练进行中也能下：训练每保存一次模型，对弈里的神经网络 AI 会自动换上新权重。下棋用 CPU，不影响训练速度。
- 棋盘的用法（布阵、摆棋编辑、悔棋、提示、上帝视角）见 README 的“人机对弈”一节。

### 数据

- 列出 `data` 下所有自对弈数据：局数、总步数、分片数、大小。
- 产新数据：选规则、填局数和随机种子，点“开始产数据”。9950X 上 20 万局约 1–2 分钟。
- **每批用不同的随机种子**，否则会产出和已有数据一模一样的棋局（页面会自动填一个新种子）。
- 新数据产完后，新建训练时把它勾上即可。

### 设置

项目目录、训练用 Python、测速目录、对弈端口。一般不用改，保存在 `JunqiStudio\settings.json`。

“程序更新”卡片显示当前程序对应的源码时间和源码最后修改时间；有新版本时点“立即更新”，没有时按钮变成“重新编译”。

## 改了代码之后

- **引擎或 Python 代码**：在工作台“总览 → 引擎自检”点“运行自检”，全部通过才算没改坏。训练或对弈服务运行时引擎文件 `junqi.dll` 被占用，需要先停掉它们。
- **工作台本身**（`desktop\JunqiStudio`）：源码更新后，工作台左上角会出现琥珀色的“有新版本 · 点此更新”，点它（或“设置 → 程序更新 → 立即更新”）就会重新编译，编译成功后点“重启并更新”，程序自动关闭、换上新版本并重新打开。训练和对弈服务在后台照常运行，设置也会保留。
  不开工作台时也可以在 `shell.bat` 里运行 `scripts\build_studio_win.bat`（需要 .NET 8 SDK；编译前先关掉工作台）。

## 不用工作台时（命令行）

双击 `shell.bat`，然后：

```bat
python -m junqi.train_bc --data data/v2_rule/four --out runs/新名称 --rules siguo_standard ^
    --steps 12000 --d-model 192 --layers 6 --heads 6 --batch 1024 --amp bf16 --lr 6e-4
python -m junqi.gen_data --rules siguo_standard --games 200000 --seed 3 --out data/v2_rule/four_s3
python -m junqi.play
```

`--out` 一定要用新目录：训练日志 `log.jsonl` 是追加写的，重复用同一个目录会把两次训练的曲线混在一起，模型也会被覆盖。

## 常见问题

| 现象 | 处理 |
|---|---|
| 总览里显卡显示“PyTorch 无法使用显卡” | 显卡驱动更新后可能出现。先点“测速”确认；不行就重装 AMD 驱动，或按 README 重建 `venv` |
| 训练速度明显低于上面的数字 | 看是不是同时跑了两个训练、或者在测速；左下角看显卡占用 |
| 自检提示 `junqi.dll is in use` | 先在工作台里停掉训练和对弈服务 |
| 对弈页一直显示“正在启动” | 看 `junqi-ai\logs\play.out` 里的报错；端口被占用时可在设置里换端口 |
| 工作台打不开 | 需要 .NET 8 桌面运行库和 WebView2（Edge 自带） |

## 安装

```bat
py -3.12 -m venv D:\junqi\venv
rem 按 AMD 文档安装 rocm_sdk_* 与 torch-2.9.1+rocm7.2.1 两组 wheel（repo.radeon.com/rocm/windows/rocm-rel-7.2.1/）
set PYTHON=D:\junqi\venv\Scripts\python.exe
scripts\check_win.bat       &rem MSVC 构建 junqi.dll + 全部自测（需要 VS 2019/2022 或 Build Tools）
scripts\build_studio_win.bat  &rem 编译工作台（需要 .NET 8 SDK）
```

AMD 的 Windows 版 PyTorch 官方只列 Win11，但在 Win10 19045 上实测可用，GPU 与 CPU 结果一致。
通过 SSH 启动的训练比在桌面会话里慢 5%–10%，长时间训练建议在本地窗口或计划任务（`schtasks /it`）里跑。
